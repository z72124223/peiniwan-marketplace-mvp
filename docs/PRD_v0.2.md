# 陪你玩 PRD v0.2

## 1. 產品定義

「陪你玩」是以遊戲為入口的 18+ 線上娛樂、關係感與技能服務市場。對外使用「遊戲社交、語音陪伴、娛樂陪練、技術陪練」描述，不以性交易、線下約會或戀愛承諾作為商品。

第一個可營運里程碑不是大型雙邊平台，而是一間由 Owner 親自經營的數位陪玩店：招募並審核陪玩師、展示可信服務、接受人工派單需求、追蹤訂單與客訴。

## 2. 目標與成功條件

### 本版目標

- 讓玩家能按「想被陪伴／想贏」找到合適服務者。
- 讓陪玩師能提交含照片、聲音、人設與技術證明的申請。
- 讓不確定人選的玩家送出「站長幫你配」需求。
- 讓單一 Owner 能查看申請、派單、客服與爭議佇列。
- 讓價格、抽成與訂單金額留下不可變更的交易快照。
- 讓台灣／全球與未來中國資料區可分離部署。

### 公開營運前供給 Gate（門檻）

- 至少 15 位已審核且可實際接單的陪玩師。
- 每週至少 50 個可預約時段。
- 每款首發遊戲在晚間熱門時段至少有 2–3 人可選。
- 每位陪玩師都有已審核照片、語音樣本、價格、時段與人設。
- 至少一半陪玩師提供新客體驗價。

### 建議追蹤指標

- 資料頁瀏覽到語音播放率、下單率與人工派單送出率。
- 首單完成率、7／30 日復購率與再次指定率。
- 情緒價值、技術、溝通、準時、描述相符的分項評分。
- 準時率、取消率、客訴率與每在線小時產值。

## 3. 角色

| 角色 | 第一版能力 |
| --- | --- |
| `player` | 探索、篩選、收藏、送出派單需求、建立訂單、完成後評價、提出客服／爭議 |
| `provider` | 申請、維護公開資料與商品、提交照片／聲音／技術證明、管理可接狀態 |
| `owner` | 審核陪玩師與證明、上／下架服務、人工派單、處理訂單／退款／爭議、凍結待撥款、查看稽核紀錄、更新在線狀態 |

資料模型保留 `staff_roles` 與 `permissions` 擴充點，但本版沒有多員工介面。

## 4. 服務與商品模型

### 服務軸

- `emotional`：娛樂與情緒價值。
- `technical`：技術陪練、教學、上分與戰術。
- `hybrid`：兼具互動氛圍與技術能力。

性別、照片、聲線、人設與互動風格可以作為服務者自願公開的搜尋條件，但不得用性別寫死服務能力。

### 後台管理的服務類別

`game_entertainment`、`game_coaching`、`ranked_companion`、`voice_chat`、`listening`、`singing`、`movie_companion`、`wake_up`、`good_night`、`cp_roleplay`、`custom_service`。

每個類別包含最低年齡、允許地區、風險等級、是否需要遊戲／技術證明、是否允許語音樣本、審核規則與啟用狀態。類別由資料層管理，前台不得用條件分支寫死。

### 計價單位

- `per_game`
- `per_30_minutes`
- `per_60_minutes`
- `package`

金額一律使用最小貨幣單位的整數，例如 NT$199 儲存為 `19900`。玩家看到的是最終價，不在結帳最後一步加收平台費。

## 5. 核心流程

### 玩家探索

1. 首頁先選「今晚想有人懂你」或「今晚想贏」。
2. 再依遊戲、服務軸、性別、聲音、人設、價格與在線狀態篩選。
3. Demo 卡片清楚標示示範照片、語音、人設、評分與價格；只有接上真實排班資料後才顯示在線或可預約狀態。
4. 玩家可查看資料頁、收藏、再次下單或送出需求。

### 陪玩師申請

1. 申請人確認年滿 18 歲並選擇服務地區。
2. 填寫公開資料、服務軸、遊戲與價格。
3. 提交照片、語音與技術證明的中繼資料。
4. 狀態進入 `submitted`，由 Owner 人工審核。
5. Owner 可要求補件、核准、拒絕或暫停。

### 站長幫你配

1. 玩家填寫遊戲、偏好、預算、時段與需求。
2. 系統建立 `concierge_request`，不自動承諾人選或價格。
3. Owner 在佇列中挑選陪玩師，更新為 `matched`。
4. 玩家確認後才能轉換為訂單；本版用假付款狀態示範。

### 客服與爭議

1. 玩家／陪玩師以訂單編號建立客服或爭議案件並附證據。
2. 系統可標記風險與排序，但不得依文字關鍵字自動封禁。
3. Owner 人工執行要求補件、凍結款項、退款、結案等動作。
4. 所有 Owner 操作寫入 `audit_logs`。

## 6. 價格與抽成

`pricing_suggestions` 依地區、遊戲、服務軸、計價單位、貨幣與生效期間提供建議區間；陪玩師仍可自行定價。

初始 `commission_rules`：

| 來源 | 平台費率 |
| --- | ---: |
| 陪玩師前 10 筆完成訂單 | 0% |
| 陪玩師自帶客 | 5% |
| 平台自然流量 | 10% |
| 平台付費推廣 | 12% |

訂單必須保存來源、平台費率、平台費、金流成本與陪玩師淨額快照，避免規則調整後改寫歷史帳務。

## 7. 地區與基礎設施邊界

- `TW` 與 `GLOBAL` 使用全球資料區；本輪部署全球私密測試版。
- `CN` 本輪只建立 `region_policy` 與 adapter（轉接介面），不正式部署。
- `PaymentGateway`、`IdentityVerificationProvider`、`StorageProvider`、`CaptchaProvider`、`NotificationProvider`、`MessagingProvider` 都必須可替換。
- 全球與中國資料區不得要求共用生產資料庫；預設只交換匿名化營運統計。

## 8. 安全、合規與內容邊界

- 玩家與陪玩師均須為 18+；本版先做明確同意與人工審核，正式上線前仍需 KYC。
- 曖昧可以是服務風格，但不得成為性交易、線下交換或消費脅迫。
- 禁止裸聊、色情影像、戀愛／見面承諾誘導、外掛作弊、冒用照片、未經同意錄音、私下收款拒絕履約。
- 評價只允許已付款且完成的訂單建立。
- 交易、審核、客服證據與稽核紀錄需定義正式保留期；中國資料依法規另行配置。

## 9. 第一版畫面

- 公開首頁與服務入口。
- 探索與篩選頁。
- 陪玩師公開資料頁。
- 陪玩師申請頁。
- 站長幫你配頁。
- Owner 總覽、申請、派單、客服／爭議佇列程式骨架；完成身份驗證與 allowlist 前不發布路由。
- 合法與禁止服務政策頁。

## 10. 非目標

本版不做自建語音、公開語音房、直播、平台幣、轉蛋、公開動態牆、原生 App、大型公會、AI 推薦、自動處罰、多層客服或中國正式部署。

## 11. 驗收條件

- 三個服務軸與三款 seed games 都來自資料層。
- 公開卡片能顯示示範照片、語音、人設、評分與價格，且不把 seed data 寫成已驗證、已完成訂單或即時在線狀態。
- 陪玩師申請與人工派單表單具有 18+、必要欄位與錯誤處理。
- Owner 工作台元件可呈現待審核、待派單、客服與爭議摘要，但未授權部署不得公開入口。
- schema、migration、RLS 草案、政策文件與 adapter 介面齊備。
- lint、typecheck、tests、build 全部通過；正式外部串接均清楚標示未啟用。
